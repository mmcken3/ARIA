# ARIA — Impeccable Design Context

## Design Context

### Users
Single technically-sophisticated user (self-hosted, personal use). Context: professional knowledge worker managing email, calendar, and tasks simultaneously. The job to be done: reduce the cognitive overhead of context-switching across tools. ARIA is always-on — it should feel like a quiet, capable presence, not a tool you have to operate.

### Brand Personality
**Thoughtful, proactive, subtle.**

ARIA notices things before you do. It surfaces the right information at the right time, without making noise about it. When it speaks, it has something worth saying. It doesn't hedge, doesn't over-explain, doesn't celebrate itself. It just works — and occasionally surprises you with how much it already knew.

### Emotional Goal
**Sharp, focused.** Zero friction. Instant answers. Feels like an extension of your own brain rather than a tool you're using.

### Reference Apps
- **Superhuman**: Clean, fast, feels expensive. No UI noise. Typography and whitespace do the heavy lifting. Dark mode is deep, not flat.
- **Arc Browser**: Opinionated, premium, high craft. Willing to make unusual decisions. Subtle personality without being playful.
- **Linear + Notion**: Refined SaaS professionalism. Data-dense without being noisy. Kanban/task patterns done properly.

### Anti-References
- Generic AI chatbot bubble UI (ChatGPT-style)
- Purple gradients on white
- Default Tailwind blue
- Anything that looks like it was scaffolded from a SaaS template
- Heavy borders, shadow-everything card layouts
- Toast notifications for everything

### Aesthetic Direction
Cool-toned neutrals with a single deliberate accent (deep teal). Both light and dark mode from day one — dark mode is deep blue-slate (not gray-black), light mode is near-white with a cool tint. Typography carries the visual quality: Instrument Serif for display/headings, DM Sans for UI/body. The type pairing creates editorial character without decorative overhead. Motion is purposeful: route transitions, message stagger, notification slide-ins. No decorative animation.

### Color Palette (Tokens)
- **Accent**: `#0D9488` (teal-600) — used sparingly: primary actions, active states, AI content markers
- **Accent subtle**: `#CCFBF1` (light) / `#134E4A` (dark) — backgrounds for accent-tinted surfaces
- **Dark mode bg**: `#0C1117` (primary), `#141B24` (secondary/surface)
- **Light mode bg**: `#F8FAFC` (primary), `#F1F5F9` (secondary/surface)
- **Text primary**: `#0F172A` (light) / `#E2E8F0` (dark)
- **Text muted**: `#64748B` (light) / `#94A3B8` (dark)
- **Border**: `#E2E8F0` (light) / `#1E293B` (dark)
- **Status**: success `#10B981`, warning `#F59E0B`, danger `#EF4444`

### Typography
- **Display / Headings**: Instrument Serif — editorial, slightly literary, adds personality to an otherwise minimal system
- **UI / Body / Labels**: DM Sans — clean, slightly rounded, excellent legibility at small sizes in both modes
- **Mono (code, IDs)**: JetBrains Mono — technical, consistent with power-user aesthetic

### Design Principles

1. **The chrome recedes, the content leads.** Sidebar, topbar, and nav are quiet. Chat messages, task cards, and AI output are the hero. If the UI frame is the most visually prominent thing, something is wrong.

2. **Speed is a design value.** No loading states that block. No spinners in the critical path. Skeleton states only. Transitions complete in under 200ms. Every interaction should feel instant.

3. **Earned emphasis.** The accent color appears so rarely that when it does, it means something. One strong call-to-action per view. Active states, not decoration.

4. **ARIA surfaces, the user decides.** Proactive content (morning brief, context strip, relevance notifications) appears without prompting — but never interrupts. It's present at the edge of attention, not demanding it.

5. **Type over decoration.** No decorative gradients. No shadows for show. No borders everywhere. Visual hierarchy comes from font weight, size, and spacing — not from graphical ornamentation.
